# Фоторамка для Android TV

Слайдшоу фотографий с телевизора или приставки. Источники: память
устройства, Яндекс.Диск и сетевая папка по SMB2/SMB3. Написано с нуля
на Kotlin и Compose.

## Как собрать APK

1. Откройте Android Studio → **Open** → выберите папку `fotoframe`.
2. Дождитесь синхронизации Gradle. При первом открытии студия сама
   предложит скачать нужный Gradle и SDK 34 — согласитесь.
3. **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
4. Готовый файл окажется в `app/build/outputs/apk/debug/app-debug.apk`.

Установка на приставку по сети:

```bash
adb connect <IP приставки>:5555
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Отладочный APK подписан временным ключом и годится для личного
использования. Для постоянной установки соберите релиз со своим
ключом: **Build → Generate Signed Bundle / APK**.

## Подключение Яндекс.Диска

Приложение читает Диск через официальный REST API. Токен нужен один раз.

Быстрый путь (без регистрации своего приложения): откройте на телефоне
[Полигон Яндекс.Диска](https://yandex.ru/dev/disk/poligon/), нажмите
получение отладочного токена, скопируйте строку и введите её в настройках
рамки. Такой токен живёт около года.

Правильный путь для постоянного использования: зарегистрируйте
приложение на https://oauth.yandex.ru/client/new, отметьте право
`cloud_api:disk.read`, и получите долгоживущий токен через обычный
OAuth-редирект. Класс `YandexDiskSource` менять при этом не придётся —
он берёт токен из настроек и ничего не знает о способе его получения.

На экран идёт превью шириной 1920 px (`YandexApi.PREVIEW_SIZE`); для
панели 4K можно поставить `"3840x"` ценой вчетверо более тяжёлых файлов.
Дата, координаты и размеры читаются из первых 128 КБ оригинала по
временной ссылке — целиком файл не скачивается.

## Как устроено

Показ и загрузка разведены. Слайдшоу крутится по локальному индексу в
SQLite и никогда не ждёт сеть. Индекс обновляется в фоне раз в шесть
часов через WorkManager, плюс вручную кнопкой в настройках.

```
источники          индекс             показ
LocalGallery  ─┐                  ┌─ PhotoPicker ── SlideshowViewModel
YandexDisk    ─┤─→ Room (photos) ─┤
SmbSource     ─┘                  └─ Coil (кэш 512 МБ)
```

Файлы, которые стоит открыть первыми:

| Файл | За что отвечает |
|---|---|
| `engine/PhotoPicker.kt` | Выбор следующего кадра, приоритет новых |
| `source/MediaSource.kt` | Интерфейс источника — точка расширения |
| `source/yandex/YandexApi.kt` | Запросы к Диску |
| `data/prefs/SettingsStore.kt` | Все настройки в одном месте |
| `ui/Transitions.kt` | Эффекты смены кадра |

## Приоритет новых снимков

Главное отличие от готовых приложений. Обычная реализация «случайно,
но поновее» сортирует коллекцию по дате и берёт случайный элемент из
первых N процентов — на архиве в двадцать тысяч снимков это последние
несколько лет, и приоритет на глаз не заметен.

Здесь работают два независимых механизма.

**Смещение выборки.** Позиция в отсортированном по дате списке берётся
как `floor(count * u^bias)`, где `u` равномерно на `[0,1)`. При `bias = 1`
это честный равномерный выбор. При `bias = 3` половина показов приходится
на самые свежие 12% коллекции, при `bias = 5` — на 3%. Настройка
показывает этот процент словами, так что ползунок понятен без пояснений.

**Пул новинок.** Снимки, попавшие в индекс за последние N дней и ещё ни
разу не показанные, живут отдельно. Заданная доля кадров берётся оттуда.
Это гарантирует, что вчерашние фотографии появятся на рамке сегодня —
независимо от размера архива. Ради этого в таблице есть отдельное поле
`firstSeenAt`, отличное от даты съёмки.

Новинкой считается снимок, у которого свежи и `firstSeenAt`, и дата съёмки:
иначе при первом обходе архива две недели «новинками» была бы вся коллекция.

Оба механизма работают поверх круга показа: пока не показаны все снимки,
повторов нет.

## Наезд на лицо

В режиме «во весь экран с наездом» камера ведёт к найденному лицу. В
режимах «целиком» (чёрные поля или размытый фон) горизонтальный снимок с
лицом появляется весь и за время показа увеличивается к лицу, пока не
уйдут боковые поля — для обычного кадра 4:3 на экране 16:9 это ×1,33, для
панорам масштаб упирается в потолок ×1,35 и поля остаются. Вертикальные
снимки и снимки без лица не двигаются. Отключается переключателем
«Наезд на лицо в режиме „целиком“».

## Управление с пульта

| Кнопка | Действие |
|---|---|
| OK | Пауза и продолжение; в истории — вернуться к показу |
| «Меню» (три полоски) | Меню действий: скрыть снимок, настройки |
| Вправо | Следующий кадр (отсчёт интервала начинается заново) |
| Влево | Предыдущий кадр из истории показа |
| Вверх | Увеличить кадр |
| Вниз | Настройки |
| Назад | Выход из настроек; в обзоре папок — на уровень выше |

Пока кадр увеличен, кнопки работают иначе — в углу экрана видна метка
масштаба с подсказкой:

| Кнопка | Действие при увеличении |
|---|---|
| Стрелки | Сдвиг кадра (восемь нажатий от края до края) |
| Каналы +/−, Zoom +/−, Page Up/Down | Ступень масштаба (1,5 → 2 → 3 → 4) |
| OK или «Назад» | Обычный размер, показ продолжается |
| «Меню» | Меню действий |

Автосмена кадра стоит, пока кадр увеличен или открыто меню.

## Очередь готовых кадров

Впереди показа держится пять готовых кадров: ссылка получена, файл
скачан в кэш, дата, место и лица разобраны. Ближайшие два раскодированы в
память в размере экрана — так `AsyncImage` попадает в кэш памяти, а не
раскодирует заново. Смена кадра начинается только когда картинка уже в
памяти: иначе анимация перехода уходит в тёмное раньше, чем появится
новый кадр. Держать раскодированными все пять нельзя — на 4K это по
33 МБ на кадр; скачанные лежат на диске и раскодируются за долю секунды.

Снимки источника, который сейчас не настроен, фильтр содержимого
исключает из показа, не удаляя из индекса.

## Эффекты смены кадра

Восемь: растворение, сдвиг вбок, сдвиг вверх, наплыв, куб, круг, шторка,
вспышка — плюс режим «чередовать все», где эффект разыгрывается заново
на каждый кадр. Длительность настраивается отдельно от интервала.

Растворение, сдвиги и наплыв целиком описываются парой «вход/выход»
Compose (`Transitions.kt`). Куб, круг и шторка так не выражаются — им
нужен доступ к самому содержимому, и они сделаны модификатором
(`TransitionEffects.kt`), который навешивается на каждый кадр внутри
`AnimatedContent` и читает ход анимации своего элемента. Всё это поворот
и обрезка слоя, то есть работа видеоускорителя.

## Картины музеев

Второй режим показа — вместо своих фотографий картины из открытых
собраний: Метрополитен-музей (европейская живопись) и Кливлендский музей
искусств, всё в общественном достоянии (CC0). Режимы не смешиваются —
это делает `ContentFilter`: в режиме картин к показу допущены только
музейные источники, в режиме фото — только свои.

Музеи — такие же `MediaSource`, как Диск и NAS (`MuseumSource.kt`).
Обход кладёт в индекс номера картин (Метрополитен) или сразу подписи и
адреса (Кливленд); `resolveDisplayUrl` скачивает картину в кэш и отдаёт
файл, поэтому размеры, лица и кадрирование работают без изменений.
Подпись Метрополитена узнаётся при первом показе и дописывается в индекс.
Фоновые проходы картины пропускают.

## Фоновая музыка

`MusicPlayer` на `android.media.MediaPlayer`. Три источника: аудиобиблиотека
устройства (MediaStore, только `IS_MUSIC`), папка на сетевом хранилище
(`SmbSource.listAudio` + `fetchToCache` — тот же кэш, что у снимков) и
поток интернет-радио по адресу. Списки перемешиваются и играют по кругу,
следующий трек с хранилища качается заранее. Игрок живёт вместе с циклом
показа: старт в `start()`, остановка в `stop()`. Для музыки с устройства
нужно разрешение `READ_MEDIA_AUDIO` (до Android 13 —
`READ_EXTERNAL_STORAGE`).

## Погода

Температура и состояние погоды подписываются рядом с часами. Включается
в настройках, город выбирается поиском по названию. Поставщиков три, все
без ключа и регистрации: Open-Meteo, api.met.no и wttr.in — пробуются по
очереди, первым тот, кто ответил в прошлый раз. Данные запрашиваются раз
в полчаса и держатся в памяти не дольше трёх часов; без сети подпись не
показывается.

Город можно определить кнопкой «Определить по сети» — по внешнему
IP-адресу подключения (ipwho.is, запасной ipapi.co). Адрес при этом уходит
этим сервисам. Найденный город нужно подтвердить: при VPN и у части
мобильных операторов город провайдера не совпадает с реальным. В списке
у каждого города видны регион и координаты — одноимённых городов много,
Санкт-Петербург есть и во Флориде.

Необязательно — Яндекс Погода по личному ключу: зарегистрируйтесь в
кабинете «Погода для умного дома» (бесплатный тариф — для некоммерческого
использования), скопируйте ключ и вставьте в поле «Ключ Яндекс Погоды».
Ключ у каждого свой: зашивать общий в приложение нельзя. С ключом Яндекс
спрашивается первым (REST v2, при отказе GraphQL v3), без ответа — по
цепочке бесплатных. Ключ удобно вводить через adb, как токен Диска. Поиск города — через Open-Meteo, при его недоступности через
OpenStreetMap.

## Пары вертикальных снимков

Два вертикальных кадра выкладываются рядом, чтобы не было широких полей.
Партнёр ищется среди непоказанных в этом цикле: сначала из той же папки,
потом из любой; если все уже показаны — самый давно показанный.

При включённом «Подбирать пару по содержимому» (по умолчанию) снимок с
людьми встаёт рядом со снимком с людьми, а кадр без людей — рядом с
таким же. Различие по числу найденных лиц, никакого распознавания
личности. Требование мягкое: не нашлось подходящего — берётся любой.
Снимки, у которых лица ещё не искали (`faceCount = -1`), под это правило
не попадают.

## Сенсорное управление

На планшете и телефоне: свайп влево-вправо листает кадры, щипок меняет
ступень увеличения, касание на увеличенном кадре возвращает обычный
размер, обычное касание — пауза. Долгое нажатие открывает меню действий
(на пульте оно на кнопке «Меню»); пункты выбираются касанием, касание
мимо меню закрывает его. Настройки — пункт в том же меню.

## Ориентация

Загрузчик применяет ориентацию из EXIF для всех форматов, включая HEIC
(`ExifOrientationPolicy.RESPECT_ALL` в `App.newImageLoader`). Поверх этого
— ручной поворот из меню кадра, хранится в `Photo.rotation`. Поворот на
90/270 сделан рамкой с переставленными сторонами, повёрнутой на месте:
вся арифметика кадрирования и наезда внутри остаётся прежней.

## Скрытие и удаление снимков

Кнопка «Меню» на пульте или долгое нажатие на сенсорном экране
открывает меню над кадром. Там два действия.

**Скрыть.** Снимок уходит с экрана, из истории и больше не выбирается.
Файл в хранилище не трогается. Список скрытых с кнопками «Вернуть» — в
настройках, ниже раздела обслуживания. Скрытие хранится в индексе
отдельно от фильтра содержимого, так что обновление списка и смена
фильтров его не сбрасывают.

**Удалить с хранилища.** Всегда в два шага: второй экран показывает имя
файла и куда он переедет. Безвозвратного удаления нет нигде, где его
можно избежать:

| Источник | Куда девается файл |
|---|---|
| Сетевая папка | В папку `_Корзина фоторамки` в корне шары |
| Яндекс.Диск | В Корзину Диска, хранится 30 дней |
| Устройство | Через системный диалог Android — в корзину галереи |

Для Яндекс.Диска нужен токен с правом `cloud_api:disk.write`: токен
только на чтение получит отказ, и на экране будет написано, какого права
не хватает.

В настройках есть кнопка «Удалить скрытые с хранилища» — отобрали
ненужное во время просмотра, убрали пачкой потом. Снимки с самого
устройства она пропускает: система требует подтверждать каждый отдельно. На пультах без кнопок каналов
масштаб меняется только вверх стрелкой «Вверх», а сброс — по OK.

## Заставка

Приложение можно выбрать как заставку в системных настройках приставки
(«Экранная заставка» / Screen saver). Показ идёт внутри самой заставки:
любое нажатие на пульте её закрывает, таймер сна приставки работает как
настроен. Настройки заставки открывают обычный экран настроек рамки.


На Google TV (Chromecast с Google TV и приставки на его базе) сторонние
заставки в системных настройках не показываются — оставлена только
своя. Включается командой с компьютера:

```
adb connect <IP приставки>:5555
adb shell settings put secure screensaver_enabled 1
adb shell settings put secure screensaver_components com.fotoframe/.FrameDreamService
```

Вернуть заставку Google — `adb shell settings delete secure screensaver_components`.
Прошивки у приставок разные, и на части из них настройку может сбросить
обновление системы — тогда команду надо повторить.

## Что можно добавить дальше

Каркас рассчитан на расширение. Ближайшее по трудоёмкости:

- **Видео.** Добавить `media3-exoplayer`, в `Photo` уже есть поле для
  длительности, в `MediaSource` — тип элемента.
- **Другие облака.** Реализовать `MediaSource` и дописать строку в
  `SourceRegistry.all`. Остальное подхватится само.
- **Расписание.** Включение и выключение по времени через AlarmManager.


## Метаданные снимков

Источники отдают далеко не всё, что нужно для красивой рамки: MediaStore
на Android 10 и новее не заполняет колонки геоданных, SMB знает только
время записи файла (для скопированного архива это дата копирования, а не
съёмки), Яндекс отдаёт превью без EXIF.

Поэтому `PhotoEnricher` досчитывает недостающее в фоне, тремя проходами
по возрастанию цены:

1. **Дата и координаты из EXIF.** У сетевой папки читается только начало
   файла — 128 КБ вместо целого снимка: сегмент APP1 по стандарту не
   превышает 64 КБ, а разница на архиве в тысячи файлов измеряется
   часами. У снимков с устройства запрашивается оригинал через
   `MediaStore.setRequireOriginal`, иначе система вырезает GPS.
2. **Названия городов** по координатам: системный геокодер, а при его
   отсутствии — OSM Nominatim с паузой между запросами.
3. **Поиск лиц** для наезда. Требует всей картинки, поэтому идёт
   последним и не задерживает подписи.

Результат пишется в индекс, так что для снимка это делается один раз за
всё время. Снимок, который прочитать не удалось, получает +1 к счётчику
попыток и уходит в конец очереди; после трёх неудач он исключается до
ручного обновления списка — кнопка в настройках обнуляет счётчики.

Подпись даты показывается только если дата настоящая (EXIF, DATE_TAKEN
из MediaStore или exif Яндекса). У файлов с сетевой папки до разбора EXIF
в `takenAt` лежит время записи файла — оно участвует в сортировке, но на
экран не выводится. Проход работает в единственном экземпляре: экран настроек и
фоновый воркер запускают его независимо, и без замка они разбирали бы
одни и те же файлы параллельно.

Чего досчитать нельзя: если GPS в файле нет (камеры без модуля
геопозиции — например, Fujifilm — его не пишут), места не будет.

Если хранилище целиком недоступно (NAS выключен), попытки снимкам не
засчитываются и пачка пропускается: иначе три ночи с выключенным NAS
исключали бы половину архива до ручного обновления.

## Удаление пропавших снимков

Файлы, исчезнувшие из источника, убираются из индекса — но только по
полному обходу и только если исчезло немного: до 50 записей или меньше
20 % коллекции. Отвалившаяся папка или пустой ответ NAS на удаление не
тянут. Два исключения: смена папки в настройках (старые записи уходят
сразу при следующем обновлении) и кнопка «Обновить и удалить пропавшие»
в разделе «Обслуживание» — для случая, когда архив переложили вручную.

## Отладка

Ход дообработки и подключение к сетевой папке пишутся в logcat:

```bash
adb -s <IP приставки>:5555 logcat -s PhotoEnricher SmbSource
```

Тесты чистой логики (даты из имён файлов, смещение выборки, арифметика
кадрирования) — `./gradlew testDebugUnitTest` или Run в Android Studio на
папке `app/src/test`.

Скрипт `tools/gps_audit.py` считает на компьютере, у скольких снимков в
папке есть координаты и дата съёмки — полезно, чтобы отличить проблему
приложения от отсутствия данных в самих файлах. Зависимостей не требует:

```bash
python3 tools/gps_audit.py /Volumes/<шара>/<папка>
```
